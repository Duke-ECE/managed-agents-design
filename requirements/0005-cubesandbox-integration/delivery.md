## Migration, rollout, and rollback

Deploy v3 manager behind a disabled flag, then runtime bridge with `NullExecutor` as default. Enable only after cross-cluster verification. Rollback disables the bridge, drains or times out calls, then manager closes remaining bindings. Keep mapping schema and Cube deployment until all bindings/orphans are reconciled. Retire v1/v2 Pod behavior only under a separate reviewed change.

The next implementation sequence, state model, failure handling, web console design, and Expo App design are specified in the [session lifecycle and client experience plan](lifecycle-and-clients-plan.md). This is a plan, not a claim that durable cleanup, client status UI, or user traffic enablement is complete. Its milestones L1-L5 must be verified independently before the runtime bridge is enabled for users.
